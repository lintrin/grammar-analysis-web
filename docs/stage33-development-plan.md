# Clause · 阶段 33 开发计划：be 地点表语与 where 提问

制定日期：2026-10-04。状态：**已规划，待实施**。起点为规则 `0.22.4`、词典 `1.7.0` 与已交付的同一 tab 检查／解析流程。本计划不表示新能力已经实现，不预设完成日期、发布版本或最终测试总数。

本阶段属于 [阶段 33–37 总开发计划](stage33-37-development-plan.md)。总路线及跨阶段约束以总计划为准；本文保留阶段 33 的细化范围和较高验收门槛。

## 1. 目标与选择理由

让学习者可以分析物体或人物“在哪里”，并查询这些表达的具体支持范围：

- `The book is on the table.`：分析主语、系动词和完整地点表语。
- `The books are not under the chair.`：识别否定，保留原文和复数一致。
- `Is the book near the car?`：识别肯定一般疑问。
- `Where is the book?`：将 where 标为被提问的地点表语。
- `The books is on the table.`：在完整且唯一的上下文中建议 is → are，应用后重新检查和解析。

当前已有六个 SV 动词的地点状语和 where 动作地点提问，但 be 系表仅接受名词短语或单形容词。先补齐这个明确缺口，可以复用现有地点词汇、原文定位与查询界面，同时建立“动作地点状语／系表地点补语”的区分，为后续介词结构扩展提供基础。

本阶段只交付这一组能力；SVO 地点附着、名词后置修饰、更多情态、复杂从句和安装包继续留在候选清单。

## 2. 首批范围

### 2.1 能力矩阵

| 维度 | 本阶段开放 | 本阶段不开放 |
|---|---|---|
| 结构 | 单简单句，显式主语 + be + 一个地点介词短语；表层句型 SVC | 多分句、嵌套、存在句 there be、倒装地点句 |
| 主语 | 现有完整主语名词短语及主格代词；保留单复数和 I/you 一致规则 | 主语省略、并列主语、范围外名词短语 |
| 谓语 | am/is/are/was/were，简单体、主动；modal=null | can/will be、完成、进行、被动以及其它系动词 |
| 陈述 | 肯定、be + not；isn't/aren't/wasn't/weren't 复用直／弯撇号 | amn't、肯定缩写、其它缩写、新否定形式 |
| 一般疑问 | Be + 主语 + 地点表语，肯定问句 | 否定疑问、do 倒装、缺 be 或自动重排 |
| 特殊疑问 | Where + am/is/are/was/were + 完整主语，肯定问句 | when/why/how、Who/What + be、额外地点尾部 |
| 地点短语 | 一个 in/on/under/near + 完整名词短语，按下表中心词白名单 | 代词地点宾语、多个地点短语、前置地点、其它介词、自由附着 |
| 时间尾部 | 新 be 地点结构与 where + be 均不带 today/yesterday | 任何额外时间词；旧结构的时间权限保持回归 |
| 其它用途 | 陈述、一般疑问和本阶段 where 提问 | 祈使、感叹、强调、附加问句 |
| 纠错 | 上述完整上下文内唯一一处限定 be 一致错误 | 插词、词序修改、改时态、改介词、改冠词、多错误或多候选 |

地点中心词仅复用现有词典，不新增词元。首批介词／中心词组合固定为：

| 介词 | 地点中心词词元（其已收录单复数均可） |
|---|---|
| in | car、bus |
| on | table、chair |
| under | table、chair |
| near | table、chair、car、bus |

地点短语沿用当前限定词、名词数、a/an 首音及前置形容词规则；必须完整消费原文。白名单不进行物理可行性或真实位置判断，未开放组合返回范围提示，不宣称语法错误。若实施前发现教学范围需要调整，先修订本文与人工答案，再实现对应规则。

### 2.2 原文与标点

沿用既有终止符约定：无句末标点可分析；有标点时陈述只接受句号、疑问只接受问号，多句／重复终止符保持现有拒绝。大小写、多空格、重复名词和弯撇号不能改变原文位置。不得通过删除介词、尾部词或添加虚构补语让输入匹配。

## 3. 教学标注与协议设计

本阶段采用项目现有五句型教学框架：be 地点结构标为 **SVC**，地点短语整体使用 `role=complement`，界面说明为“地点表语”。这是本项目固定的教学标注约定，实施前须在人工范围文档中说明；不能复用 SV 动作地点的 adverbial 标注。

| 输入 | 人工目标分类与节点 |
|---|---|
| `The book is on the table.` | complete；declarative / SVC / simple / present / simple / active；主语 The book、谓语 is、表语 on the table |
| `The book was near the tall table.` | complete；past；整个 near 短语为表语，tall 为其子定语 |
| `Is the book on the table?` | complete；interrogative / yes-no / SVC；谓语 Is，主语 the book，表语 on the table |
| `Where is the book?` | complete；interrogative / wh-complement / SVC；表语 Where，谓语 is，主语 the book；不补虚构地点 |
| `She sleeps near the table.` | 保持旧 SV、地点 adverbial 和原有完整答案 |
| `Where does she work?` | 保持旧 wh-adverbial、SV 和原有完整答案 |

所有完整新结构 `modal=null`；多分句仍不获得新地点权限。采用以下直接协议升级：

1. `QuestionType` 新增 `wh-complement`。where + be 使用该分类，避免混入现有动作状语提问。
2. 顶层及分句类型、运行时校验、分类标签、完整答案比较工具与 fixture 同步更新；本阶段不新增 Role，继续使用 complement。
3. `wh-complement` 只允许单简单句、SVC、简单体、主动、非情态 where + 限定 be。where 必须对应原文显式 complement 节点，不能接受其它疑问词或缺失表语节点。
4. 原 wh-subject / wh-object / wh-adverbial 继续保持当前 SV/SVO 边界，不能因为新增分类而放宽。
5. 旧结构当前答案原则上保持不变；旧范围外输入若进入新范围，逐条保留原句、旧答案、迁移原因及新完整答案。不接受缺字段旧协议，不保留双协议分支。

## 4. 数据与实现影响

当前词典校验把 finite-be 功能词限定为恰好一个 SVC 搭配，补语类型只包含名词／单形容词；地点 fixedTail 只允许六个 SV。现有 where 词条也只有 wh-adverbial 用途。这些都是需要显式修改的生产约束。

- **词典模型**：为地点表语新增明确的补语描述与许可数据，区分于 SV 的 fixedTail。33A 冻结具体字段与唯一存储来源；介词／中心词清单必须可供解析、构建校验和查询共同读取，不复制多份可漂移的名单。
- **be 搭配**：审核 finite-be 词条的 SVC 地点搭配及与旧系表搭配的候选选择；放宽“恰好一个 frame”时仍限制为实际开放的 be 搭配，不能允许任意功能词携带任意 frames。
- **where 用途**：显式增加表语提问用途；更新相关功能词用途枚举、用途／词性校验和来源说明，保留动作状语提问用途。
- **存储与发布**：同步 Zod、SQLite 模型、SQL 迁移及冻结保护、导入／审核／发布、客户端生成和 verify。新修订绑定新哈希重新审核，已有发布不覆盖；必要时直接升级词典格式版本并更新所有现行读写与固定答案。
- **解析入口**：在完整结构层面区分 be 地点补语和原 SV 地点状语；检查陈述、否定、一般疑问、where 及其它用途入口。共享候选预算，不使用“先截掉地点再视为旧完整句”的兜底规则。
- **入口与候选保护**：现行特殊疑问／地点入口先于 will 和其它谓语规则返回，须调整识别与分派，避免新 be 地点结构被旧入口提前拒绝。be 旧名词／形容词表语与新地点搭配分别匹配；不能给旧完成系表、can/will be、感叹或分句自动增加地点权限。
- **界面与查询**：更新 SVC 说明、疑问分类、地点表语中文解释、例句分类、where／be／介词的逐搭配能力说明和限制。新例句不会自动分析，沿用当前选择后触发分析的流程。

主要涉及 `lib/grammar/`、`app/page.tsx`、`components/dictionary-query.tsx`、`scripts/lexicon/`、`db/schema.ts`、`drizzle/`、`data/grammar/` 和词典发布数据。具体文件修改在 33A 形成可检查的清单。

## 6. 人工答案与回归门槛

### 6.1 开发集（实现前冻结）

- 至少 **48 个正确句**：肯定陈述、否定陈述、肯定一般疑问、where 提问各不少于 12 个。
- 至少 **16 组纠错／完整控制答案**，每类结构不少于 4 组；包含现在／过去、I/you、单复数及已开放缩写。缩写必须整体精确修改，不拆开原文区间。
- 至少 **40 个无建议对照**：未知词、白名单外介词／中心词、缺 be／缺地点名词、错误限定词／冠词、双地点、时间尾部、词序、否定疑问、can/will／完成／进行／被动、其它疑问词、祈使／感叹、多分句及多错误。
- 正确句覆盖全部 10 个介词／中心词配对、四种结构、现在／过去、主语形态、地点名词单复数、内部定语、无标点、多空格与大小写。

固定 status、实际诊断、分类、节点角色、UTF-16 区间、父子关系、规则 ID、精确编辑，以及应用后完整结果。拒绝输入按现有检测顺序固定原因；未收录词与未支持结构不混同于语法错误。

新边界必须防止错给建议，例如 `Where the book is?` 不自动重排，`The book is on table.` 不自动加冠词，`The book has been on the table.` 只提示未开放范围。新 be 一致纠错先确认完整主语、许可地点／疑问结构、唯一解析和单处错误，再确定同一时态下的 be 替换。

### 6.2 独立验收（开发冻结后另行人工编写）

至少 **40 个正确句**（四类各 10 个）、**12 组安全纠错／控制答案**、**24 个无修改边界**，另有至少 **8 个独立查询流程**。查询覆盖 be 旧／新搭配、where 两种用途、介词许可、词性筛选、例句应用与未收录提示；对照例句不得越过数据矩阵。

独立输入不能重复历史开发／验收、本阶段开发、界面／文档例句、迁移句或控制句。阶段 32 独立集保留为历史回归，不计入新独立样本。保存冻结来源与哈希，记录第一次行为验证的发现；失败时修复实现，不删原句、不削弱断言、不反向生成答案。

### 6.3 既有行为必须保留

五种句型、四种用途、旧 SVC 名词／形容词表语、can/will be 旧系表、旧完成系表、六个 SV 地点状语、全部特殊疑问、五个新 SV、拥有义 have、缩写、被动和两分句均继续完整回归。尤其验证：be 后的形容词不被当作地点、旧 where 动作提问不变、其它新结构不自动进入分句或情态链、失败结果不泄露成分或建议。

## 7. 联合验收与完成标准

工程命令沿用当前项目：

```sh
npm test
npx tsc --noEmit
npm run lint
npm run lexicon -- verify
npm run build
git diff --check
git diff --cached --check
```

此外必须完成：

1. 空 SQLite 工作库初始化、迁移及从新固定发布重建；确定性导出比对，未审核／过期哈希／篡改数据拒绝，冻结记录保护。旧发布和原始 fixture 哈希保持不变。
2. 开发与最终构建两种服务的浏览器验收，1280px／390px 下验证输入 → 检查 → 地点表语／where 解析 → 查看内部定语，以及纠错 → 应用 → 重新检查；对照原地点状语和多分句。
3. Ctrl/⌘+Enter、键盘选择与焦点、未知词定位、查询及例句应用、编辑即时失效、连续点击、失败重试、待处理回调取消，以及规则／词典版本和哈希真实 HMR 失效。
4. 静态资源加载后断网运行；句子和搜索词不进入网络、控制台、服务端日志或浏览器持久存储，刷新恢复默认状态。维护数据库不可用时构建网页仍可分析。
5. 1000/1001 UTF-16 边界、共享 4000 预算、预算耗尽、长形容词短语、同形词和多搭配；记录基线／新版本本机耗时、资源体积及长任务。若出现可重复退化，定位修复或明确记录未解决限制，不能直接以旧性能证据通过。
6. 更新 README、文档导航、当前功能清单、查询教学数据、词典协议和交付证据；截图人工查看，结果状态和原因对照固定答案。

任何子阶段有未解决阻断或缺少证据，保持“待实施／实施中／待验收”，不能标注完成。源码推送和公开部署不属于本阶段默认交付。
