# 阶段 10A：后置 because 原因从句

> 已归档（2026-10-03）：本页保留对应阶段的计划、范围与验收记录；文中“当前”和“下一步”属于当时版本。现行能力见 [项目说明](../../README.md#当前进度)，后续开发见 [阶段 27–32 计划](../structure-development-plan.md)，历史导航见 [归档索引](README.md)。

规则版本 `0.7.0`；状态 **✅ 已完成**（2026-10-02）。以下范围与人工答案先于规则实现固定。

- 仅接受 `主句 + because + 原因从句`，无逗号；句末可有一个句号，保留大小写、多空格及原始 UTF-16 位置。两侧均为显式主语、可完整匹配阶段 8 规则的陈述结构。
- 不接受前置 because、if、多重连接、并列嵌套、关系/宾语从句、省略主语、其他用途或其他标点。不推断两分句在语义上是否构成合理因果。
- 顶层 complexity 为 complex，purpose 为 declarative，pattern 与 tense 为空；两个 clause 根节点依次标记 main / subordinate，内部成分与定语通过 parentId 归属。connector 根节点记录 cause 和 because 的原文区间。原因从句说明主句发生的原因，界面按分句查看句型与时态。
- 任一分句形式错误、未知、范围外、歧义或预算耗尽，整句降级，不输出成分或修改建议；多分句暂不提供纠错。全句共享 4000 次边界预算与 1000 UTF-16 输入限制。

人工预期见 `tests/fixtures/stage10a.json`：12 个正确句，33 个边界/错误句。正确句均固定用途、主从归属、句型、时态、原文区间、定语层级与无纠错预期；覆盖五种句型、否定、can、不同主语、混合时态、重复词、大写、多空格和无句末标点。保留此前全部输入与断言；阶段 8 的既有并列迁移从 0.6.0 起持续生效，阶段 9 的混合 because/and 边界仍不支持。
